# Prior work and baselines for the Verifier-Anchored RL paper (AAAI)

Source: deep-research workflow (2026-06-22), 105 agents, adversarially verified. Anchors the related-work section and baseline selection.

## Executive summary

The submission sits at the dense intersection of four well-populated 2024-2026 research lines, and an AAAI 2026 reviewer will expect direct comparison against the canonical methods in each. The single closest prior work - and the most likely "you didn't compare against X" target - is AlphaMath (arXiv:2405.03553), which already instantiates almost every structural element of the proposed framework: a value/Q head appended to a shared base LLM (tanh head), MCTS used as a policy-improvement/data-generation operator (not the online learner) over K=3 expert-iteration rounds with only 15k QA pairs and 0 annotated solution processes, a terminal +/-1 answer-correctness reward, and an explicit greedy-vs-search compute-vs-accuracy frontier (greedy 59.7/33.2 -> MCTS/SBS ~83-84/64-66 on GSM8K/MATH at 7B). The proposed paper's defensible novelty is therefore NOT MCTS-as-distillation or terminal answer-checking per se (AlphaMath partially preempts both), but the combination of (a) reward anchored ENTIRELY in a non-LLM verifier at both training AND inference - AlphaMath, ReST-MCTS*, rStar-Math, and MCTS-DPO all fall back on a learned value model / PPM / PRM / model self-evaluation at intermediate or inference-time nodes - and (b) the explicit small-set coarse-cognitive-verb action space (decompose, compute-subexpression, form-hypothesis, invoke-verifier, backtrack, commit-answer), of which rStar (arXiv:2408.06195) is the closest analogue with five human-like actions but no explicit invoke-verifier/backtrack and no training. The required baselines cluster into search/test-time-compute (rStar, rStar-Math, AlphaMath, ToT/RAP, self-consistency), AlphaZero-for-reasoning / expert-iteration (STaR, ReST-EM, V-STaR, TS-LLM, ReST-MCTS*, MCTS-DPO), and verifier/PRM-guided selection (Math-Shepherd, "Let's Verify", best-of-N), evaluated on GSM8K/MATH with pass@1/greedy reported separately from search-augmented accuracy and increasingly against a test-time compute (sims/tokens) budget.

## Verified findings

### AlphaMath is the closest existing method and the single most dangerous 'did you compare against X' objection: it already embodies a shared-base value/Q head (tanh head), MCTS as a policy-improvement/data-generation operator (not the online learner) over K=3 expert-iteration rounds, training on only 15k QA pairs with 0 annotated solution processes, and a terminal +/-1 answer-correctness reward.
- confidence: high | vote: 3-0 (across constituent claims [3],[4],[5])
- sources: https://arxiv.org/abs/2405.03553
- evidence: AlphaMath appends 'an auxiliary linear layer with a tanh activation function' so policy and value 'share the majority of their parameters' (claim [3]). It is 'Process Supervision without Process': MCTS generates training data, distilled into policy+value over 'K=3 rounds' using a training set of 'only 15k question-answer pairs and 0 solution processes' (claim [4]). Reward is non-learned at terminal nodes: 'r = 0 to all non-terminal reasoning steps, and r = +/-1 to a correct/incorrect final answer' (claim [5]). This structurally preempts MCTS-as-distillation, the shared Q/value head, and terminal verifier-anchoring - so the paper must distinguish itself sharply from AlphaMath. NOTE the claim that AlphaMath uses a 'frozen-style' base is wrong: AlphaMath FULLY fine-tunes the base jointly with the value head, whereas the proposed framework distills into heads on a FROZEN base - a genuine architectural difference the paper can press.

### AlphaMath's verifier-anchoring is only PARTIAL - it uses the non-learned +/-1 answer check only to TRAIN a learned step-level value model, then at inference 'consistently rel[ies] on the value model for node evaluation, including for terminal nodes' - leaving a defensible novelty gap for a framework that keeps the non-LLM verifier in the loop at inference time too.
- confidence: high | vote: 3-0
- sources: https://arxiv.org/abs/2405.03553
- evidence: Claim [5]: AlphaMath uses the answer-anchored reward 'only to TRAIN a learned step-level value model V_phi'; at inference 'we cannot verify the correctness of a path during inference. Therefore, we consistently rely on the value model for node evaluation, including for terminal nodes.' Thus the proposed 'verifier-anchored rather than learned-reward-model' distinction is only PARTIALLY preempted: AlphaMath abandons verifier anchoring at inference. This is precisely where the proposed framework (symbolic solver / unit-test / proof checker driving reward at both train and inference, including the explicit invoke-verifier action) carves out defensible novelty.

### AlphaMath provides a concrete same-base compute-vs-accuracy frontier at ~7B that the proposed paper's greedy(B=0)-vs-search(B>0) frontier should be benchmarked against: greedy 2-shot 59.7/33.2, AlphaMath K=3 73.5/53.6, step-beam-search SBS(B1=3) 84.1/66.3, MCTS(B1=1, N=40) 83.2/64.0 on GSM8K/MATH (DeepSeekMath-Base 7B, no SFT seed solutions).
- confidence: high | vote: 3-0
- sources: https://arxiv.org/abs/2405.03553
- evidence: Claim [6]: Table 2 of AlphaMath gives '+our prompt 2-shot 59.7 33.2 ... +AlphaMath (K=3) 73.5 53.6 ... +SBS (B1=3) 84.1 66.3 ... +MCTS (B1=1) 83.2 64.0' (GSM8K/MATH), with seed-data size = 0 and N=40 MCTS sims by default. This is the canonical accuracy-vs-search-budget table an AAAI reviewer will expect the proposed frontier to be juxtaposed against - but note the 7B scale vs the proposed ~1.5B substrate, so it is a strong-baseline target rather than a same-base comparison.

### rStar (2408.06195) is the closest prior method on the ACTION-SPACE axis: it defines a discrete, coarse, human-like five-action MCTS space (one-step thought, remaining steps, propose sub-question+answer, re-answer sub-question, rephrase) for small LMs - but it is inference-only (no fine-tuning, no superior model) and uses second-SLM mutual-consistency rather than a non-LLM verifier, so it contrasts on both training and reward.
- confidence: high | vote: 3-0 (claims [7],[8],[9])
- sources: https://arxiv.org/html/2408.06195v1
- evidence: Claim [8]: rStar's five actions A1-A5 ('Propose an one-step thought', 'Propose the remaining thought steps', 'Propose next sub-question along with its answer', 'Answer the sub-question again', 'Rephrase the question/sub-question') closely parallel the proposed coarse-cognitive-verb space, and rStar's related work notes competing MCTS-for-LLM methods (RAP, AlphaMath/MindStar) use a SINGLE action type - making rStar the closest multi-action analogue. Gap: rStar has no explicit invoke-verifier or backtrack action. Claim [7]: rStar 'significantly improves... SLMs without fine-tuning or superior models' (purely inference-time), contrasting with the proposed expert-iteration/distillation training. Claim [9]: rStar 'exclude[s] self-rewarding techniques for any intermediate nodes due to the limited capabilities of SLMs', using a similar-capability second-SLM discriminator for mutual consistency - an LLM-internal signal, NOT a non-LLM verifier, so it differs from the proposed verifier-anchored reward.

### rStar-Math (2501.04519) is the most prominent small-LM (1.5B-7B) + MCTS + reward-model + GSM8K/MATH baseline and a near-certain required comparison; crucially its step-reward signal is a LEARNED Process Preference Model (PPM), making it the canonical foil for the 'verifier-anchored (not learned) reward to reduce Goodhart' thesis.
- confidence: high | vote: 3-0 / 2-1 on the headline numbers (claims [0],[1],[2])
- sources: https://arxiv.org/abs/2501.04519
- evidence: Claim [0]: rStar-Math uses MCTS as test-time 'deep thinking' across 'four SLMs (1.5B-7B)', exactly the scale of interest. Claim [1]: its step-scoring reward is a learned 'process preference model (PPM)' - 'the key determinant of the upper performance limit' - precisely the Goodhart-prone learned RM the proposed framework rejects; this is the most likely 'you didn't compare against rStar-Math' objection. Claim [2] (2-1): MATH accuracy jumps from 58.8% to 90.0% (Qwen2.5-Math-7B) and 41.4% to 86.4% (Phi3-mini-3.8B). CAVEAT: those are SEARCH-augmented numbers on a strong Qwen2.5-Math base (not greedy, not the ~1.5B generic substrate), so comparison must be apples-to-apples on the B>0 setting and matched test-time-compute budget. NUANCE: rStar-Math is not purely learned-reward - it uses Python code execution as a non-LLM filter and ground-truth terminal answer correctness to bootstrap Q - but the STEP reward model is unambiguously learned (PPM).

### ReST-MCTS* (NeurIPS 2024) is a co-closest method on the MCTS-as-distillation/expert-iteration axis - MCTS* is a policy-improvement/data-generation operator producing traces + per-step values used to self-train policy and reward models over multiple iterations - but it anchors reward in a LEARNED process reward model whose value targets are inferred from oracle final answers, again contrasting with a pure non-LLM verifier.
- confidence: high | vote: 3-0 (claims [10],[11]); refuted sub-claim on same-budget search comparison noted
- sources: https://proceedings.neurips.cc/paper_files/paper/2024/file/76ec4dc30e9faaf0e4b6093eaa377218-Paper-Conference.pdf
- evidence: Claim [10]: ReST-MCTS* integrates 'process reward guidance with tree search MCTS* for collecting higher-quality reasoning traces as well as per-step value to train policy and reward models', continuously enhancing the LM 'for multiple iterations' - MCTS as data generator, not core learner. Claim [11]: it trains a learned PRM ('we simply train a process reward model V_theta... a variant of common PRM'); oracle final answers are used to INFER per-step process rewards that 'act as value targets for further refining the process reward model.' So it shares the distillation axis with the proposal but diverges on reward anchoring. TRANSPARENCY: a claim that ReST-MCTS* beats Best-of-N/ToT/Self-Consistency on a MATCHED search budget with an explicit accuracy-vs-completion-token curve was REFUTED (1-2) - do not assert that ReST-MCTS* supplies a matched-budget frontier.

### MCTS-DPO (arXiv:2405.00451) is a relevant AlphaZero-inspired baseline that uses MCTS as a policy-improvement/data-collection operator (look-ahead breaks instance rewards into step-level signals distilled via DPO), reaching 81.8% GSM8K / 34.7% MATH on Mistral-7B (+5.9/+5.8 over SFT); its reward combines outcome validation with MODEL self-evaluation, not a pure non-LLM verifier.
- confidence: high | vote: 3-0 (claims [12],[13],[14])
- sources: https://arxiv.org/abs/2405.00451
- evidence: Claim [12]: 'leverages Monte Carlo Tree Search (MCTS) to iteratively collect preference data... break down instance-level rewards into more granular step-level signals... employs Direct Preference Optimization (DPO) to update the LLM policy' in a loop 'inspired by... AlphaZero.' Claim [13]: reward R(s_t)=O(s_t)+C(s_t) combines outcome validation O with model self-evaluation C = pi_theta(A|...), i.e. NOT a pure symbolic/unit-test/proof-checker reward - another Goodhart-exposed foil. Claim [14]: on Mistral-7B, GSM8K 81.8% (+5.9%), MATH 34.7% (+5.8%), ARC-C 76.4% (+15.8% vs a weaker reference; only +2.5% vs SFT).

### The expert-iteration lineage the paper must cite and position against runs STaR -> ReST/ReST-EM -> V-STaR -> TS-LLM. STaR is the foundational bootstrapping template; ReST-EM is the EM-style Generate/Improve loop with a non-learned binary correctness filter (a direct precedent for verifier-anchored reward); V-STaR adds a DPO-trained verifier used as a best-of-N reranker; TS-LLM is the AlphaZero-like learned-value tree-search loop used at both inference and training.
- confidence: high | vote: 3-0 (claims [15],[16],[17],[18],[19],[20],[21],[22],[23])
- sources: https://arxiv.org/abs/2203.14465, https://arxiv.org/pdf/2312.06585, https://arxiv.org/abs/2402.06457, https://arxiv.org/abs/2309.17179
- evidence: STaR ([23], NeurIPS 2022): iterative loop of few-shot rationale generation, rationalization (rationale conditioned on the correct answer for wrong items), fine-tune on rationales yielding correct answers, repeat - the canonical self-improvement template. ReST-EM ([20],[21],[22], TMLR 2024): EM-style Generate(E-step, sample + binary-reward filter)/Improve(M-step, fine-tune); 'binary rewards (either 0 or 1)' from ground-truth answer-checking (MATH) and test-case execution (APPS) - NON-learned verifier reward, the strongest precedent for the proposed Goodhart-avoidance framing; and 'fine-tuning on model-generated solutions substantially outperforms using human-written solutions' (sample-efficiency / beyond-human-data argument). V-STaR ([15],[16],[17], COLM 2024): trains a verifier via DPO on BOTH correct and incorrect generations (unlike STaR which discards incorrect), used at inference as a best-of-N ranker, '4% to 17% test accuracy improvement' over self-improvement/verification baselines on LLaMA2. TS-LLM ([18],[19], ICML 2024): AlphaZero-like tree search with a LEARNED value function (vs ToT/RAP which prompt a pre-trained model as the value function), guiding LLMs 'during both inference and training, iteratively improving the LLM' via a policy-improvement/distillation/evaluation cycle.

### The defensible novelty triangulates to: (a) a non-LLM verifier as the SOLE reward anchor at BOTH training and inference (every close method - AlphaMath, ReST-MCTS*, rStar-Math, MCTS-DPO - reverts to a learned value model / PPM / PRM / model self-evaluation at intermediate or inference nodes; only ReST-EM uses a pure non-learned reward, and it has no MCTS/search frontier); (b) MCTS strictly as a policy-improvement/distillation operator into Q/policy heads on a FROZEN base (vs AlphaMath/TS-LLM which fully fine-tune); (c) an explicit greedy(B=0)-vs-search(B>0) compute-vs-accuracy frontier; (d) a small coarse-cognitive-verb action space that uniquely includes invoke-verifier and backtrack (rStar's five actions are the closest but lack these).
- confidence: medium | vote: synthesis of 3-0 claims; positioning judgments are editorial
- sources: https://arxiv.org/abs/2405.03553, https://arxiv.org/abs/2501.04519, https://proceedings.neurips.cc/paper_files/paper/2024/file/76ec4dc30e9faaf0e4b6093eaa377218-Paper-Conference.pdf, https://arxiv.org/abs/2405.00451, https://arxiv.org/pdf/2312.06585, https://arxiv.org/html/2408.06195v1
- evidence: No single confirmed claim asserts the full novelty package, but it is supportable by the conjunction: ReST-EM uses a non-learned binary verifier but no search frontier (claims [20],[21]); AlphaMath/ReST-MCTS*/rStar-Math/MCTS-DPO all have search/distillation but learned-reward or self-eval components at inference (claims [1],[5],[11],[13]); the frozen-base distillation contrasts with AlphaMath's full fine-tune (claim [3] correction) and TS-LLM's training loop (claim [19]); the invoke-verifier/backtrack verbs go beyond rStar's five generative actions (claim [8]). Confidence is medium because the 'sole anchor at inference' and 'uniquely includes invoke-verifier' claims rest on the absence of a closer method in the surveyed set, not on a positive primary source - a reviewer could surface an unsurveyed tool-integrated method (e.g., a verifier-in-the-loop search variant).

### The most likely AAAI 2026 'you didn't compare against X' objections, in priority order: (1) AlphaMath (nearest neighbor on architecture+distillation+terminal reward); (2) rStar-Math (the headline small-LM MCTS+RM result on GSM8K/MATH); (3) rStar (nearest neighbor on coarse action space at SLM scale); (4) ReST-MCTS* and MCTS-DPO (MCTS-as-expert-iteration); plus REQUIRED non-search/ablation baselines: greedy/pass@1, self-consistency (majority voting), best-of-N with the verifier, STaR/RFT, ReST-EM, and an outcome/process-reward-model-guided search (Math-Shepherd / 'Let's Verify Step by Step' style).
- confidence: medium | vote: synthesis; individual method facts 3-0, prioritization is editorial
- sources: https://arxiv.org/abs/2405.03553, https://arxiv.org/abs/2501.04519, https://arxiv.org/html/2408.06195v1, https://proceedings.neurips.cc/paper_files/paper/2024/file/76ec4dc30e9faaf0e4b6093eaa377218-Paper-Conference.pdf, https://arxiv.org/abs/2405.00451, https://arxiv.org/abs/2402.06457, https://arxiv.org/pdf/2312.06585, https://arxiv.org/abs/2203.14465, https://arxiv.org/abs/2309.17179
- evidence: AlphaMath, rStar-Math, rStar, ReST-MCTS*, MCTS-DPO are all confirmed-as-adjacent by claims [0]-[14]. Standard evaluation conventions confirmed across these sources: GSM8K + MATH as the core benchmarks (rStar-Math also AIME; AlphaMath also reports per-budget search), pass@1/greedy reported separately from search-augmented accuracy, and increasingly an accuracy-vs-search-budget axis (AlphaMath SBS B1 / MCTS N=40 sims; rStar 32 MCTS rounds; the B knob).
